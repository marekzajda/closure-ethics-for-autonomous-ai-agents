Scénarios de référence exécutables

Exemples pratiques de Closure Ethics en code.

Sept scénarios concrets fondés sur l’implémentation de référence publique. Ils utilisent DEMO_POLICY et les structures de données réelles de closure_ethics.py.

Exemples exécutables ↗Implémentation
Important : DEMO_POLICY est un profil de démonstration. Un déploiement réel doit définir, auditer et versionner ses propres seuils.

Configuration commune

from closure_ethics import *

def I(x):
    return Interval.point(x)

governor = ClosureEthicsGovernor(DEMO_POLICY)
1 · Sandbox

Déploiement direct vs canary en sandbox

Le canary à utilité plus faible est choisi parce qu’il préserve auditabilité, réparation bornée, réversibilité et pluralité d’agence.

2 · Repair

L’utilité élevée ne compense pas l’absence de voie de réparation

task_utility=1.0 ne rend pas admissible une action sans bounded repair.

3 · Deception

L’obéissance aveugle ne suffit pas

Une action totalement autorisée peut être refusée si le risque de dissimulation ou de persistance secrète est élevé.

4 · Agency

Perte de pluralité d’agence

Une forte concentration de capacité déclenche AGENCY_LOSS.

5 · Composition

Admissible localement, inadmissible conjointement

Les actions conjointes sont réévaluées ; les scores locaux ne sont jamais simplement moyennés. La composition peut échouer pour AUDITABILITY_LOSS.

6 · Pareto repair

Recherche bornée d’un chemin de réparation

Les budgets de coût et de risque doivent être satisfaits simultanément ; le chemin retenu est ('x', 'b', 'safe').

7 · Recovery

Mode de récupération

Si les actions primaires échouent, un candidat de récupération admissible peut être choisi avec EXECUTE_RECOVERY.

Intégration dans un agent

candidates = planner.propose(state)
evidences = [domain_adapter.to_evidence(c, state) for c in candidates]
decision = governor.choose(evidences, recovery_candidates=recovery_evidences)

if decision.status in ("EXECUTE", "EXECUTE_RECOVERY"):
    executor.run(decision.selected_action)
else:
    escalation_queue.submit(decision.to_json())

selected_action est un identifiant d’action qui doit être résolu vers un candidat enregistré avant exécution.
