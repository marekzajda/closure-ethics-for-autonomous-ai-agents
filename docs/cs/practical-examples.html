Spustitelné referenční scénáře

Praktické příklady implementace Closure Ethics.

Sedm konkrétních scénářů založených na veřejné referenční implementaci. Používají DEMO_POLICY a skutečné datové struktury z closure_ethics.py, takže nejde jen o pseudokód.

Spustitelné příklady ↗Referenční governor ↗Specifikace implementace
Důležité: DEMO_POLICY je demonstrační profil, nikoli univerzální morální konstanta ani hotové produkční prahy. Reálné nasazení musí definovat, auditovat a verzovat vlastní politiku.
Společný základ

Přímé použití referenčního governoru

from closure_ethics import *

def I(x):
    return Interval.point(x)

governor = ClosureEthicsGovernor(DEMO_POLICY)

Kompletní spustitelná verze všech sedmi scénářů je v souboru 09-implementation/practical_examples.py. Níže je jejich význam a očekávané rozhodnutí.

1 · Sandbox

Přímý deploy vs. sandboxed canary

Přímý deploy má vysokou task utility, ale ztrácí auditovatelnost, repair path, reverzibilitu a pluralitu agentury. Governor proto vybere sandboxed-canary se statusem EXECUTE.

decision = governor.choose([unsafe, safe])
print(decision.status)          # EXECUTE
print(decision.selected_action) # sandboxed-canary
2 · Repair

Vysoká utilita nekompenzuje chybějící repair path

Akce s task_utility=1.0 a bez bounded repair zůstává nepřípustná. Governor zvolí níže odměňovanou variantu s opravnou cestou.

d = governor.choose([bad, good])
# selected_action == "lower-reward-with-repair"
3 · Deception

Slepá poslušnost nestačí

Plná autorizace sama nestačí, pokud akce nese vysoké riziko concealment nebo covert persistence. Výsledkem je REFUSE_OR_ESCALATE a důvod REFUSE_COVERT_ACTION.

4 · Agency

Ztráta plurality agentury

Silná koncentrace praktické kapacity do jednoho aktéra vyvolá AGENCY_LOSS. Metrika sleduje jak individuální retenci, tak efektivní pluralitu.

ev = evaluate(centralize, DEMO_POLICY)
print(ev.violations)  # ('AGENCY_LOSS',)
5 · Composition

Multi-agentní kompozice: lokálně OK, společně špatně

Dvě lokálně přípustné akce mohou vytvořit společný přechod s nízkou auditovatelností. Proto se joint action znovu vyhodnocuje a lokální skóre se neprůměrují.

print(evaluate(local1, DEMO_POLICY).admissible)          # True
print(evaluate(local2, DEMO_POLICY).admissible)          # True
print(governor.evaluate_joint_action(joint).admissible)  # False
Klíčový bod: přípustnost není automaticky uzavřená vůči kompozici.
6 · Pareto repair

Bounded repair-path search

Pareto label-setting search musí současně splnit rozpočet nákladů i rizika. Levná, ale příliš riziková cesta je odmítnuta ve prospěch bezpečnější cesty ('x', 'b', 'safe').

cert = bounded_repair_search(
    graph, start="x", safe_states={"safe"}, max_cost=6, max_risk=3
)
print(cert.exists)  # True
print(cert.path)    # ('x', 'b', 'safe')
7 · Recovery

Recovery režim

Když všechny primární akce selžou, governor použije stejné invarianty na explicitní recovery kandidáty. Bezpečnější sandbox-and-log může být vybrán jako EXECUTE_RECOVERY.

d = governor.choose(
    candidates=[unsafe],
    recovery_candidates=[recovery],
)
# status == "EXECUTE_RECOVERY"
# selected_action == "sandbox-and-log"
Zapojení do agenta

Typický vzor planner → governor → executor

# 1. Planner navrhne kandidáty
candidates = planner.propose(state)

# 2. Doménové adaptéry vytvoří auditovatelné ActionEvidence
evidences = [domain_adapter.to_evidence(c, state) for c in candidates]

# 3. Governor rozhodne
decision = governor.choose(evidences, recovery_candidates=recovery_evidences)

# 4. Provede se jen vybraná přípustná akce
if decision.status in ("EXECUTE", "EXECUTE_RECOVERY"):
    executor.run(decision.selected_action)
else:
    escalation_queue.submit(decision.to_json())

V produkční integraci je selected_action identifikátor akce. Executor by jej měl rozlišit vůči registru kandidátů, nikoli zacházet s libovolným textem jako se spustitelným příkazem.

Hranice odpovědnosti: governor rozhoduje nad strukturovanými důkazy; doménové adaptéry zůstávají odpovědné za uzemnění škody, autorizace, klamání a dalších vstupních veličin.
