Gemeinsames Setup

from closure_ethics import *

def I(x):
    return Interval.point(x)

governor = ClosureEthicsGovernor(DEMO_POLICY)
1 · Sandbox

Direktes Deployment vs. Sandbox-Canary

Die niedrigere Task-Utility gewinnt, weil Auditierbarkeit, Repair-Pfad, Reversibilität und Agency-Pluralität erhalten bleiben. Ergebnis: sandboxed-canary.

2 · Repair

Hoher Nutzen ersetzt keinen Repair-Pfad

task_utility=1.0 kompensiert fehlende bounded repair nicht.

3 · Deception

Blinder Gehorsam reicht nicht

Auch eine vollständig autorisierte Aktion wird bei hohem Concealment- oder Covert-Persistence-Risiko mit REFUSE_OR_ESCALATE abgelehnt.

4 · Agency

Verlust von Agency-Pluralität

Starke Machtkonzentration löst AGENCY_LOSS aus.

5 · Composition

Lokal zulässig, gemeinsam unzulässig

Joint actions werden neu bewertet; lokale Scores werden nicht gemittelt. Eine gemeinsame Aktion kann deshalb wegen AUDITABILITY_LOSS scheitern.

6 · Pareto repair

Begrenzte Repair-Pfad-Suche

Kosten- und Risikobudget müssen gleichzeitig eingehalten werden; der sichere Pfad ist ('x', 'b', 'safe').

7 · Recovery

Recovery-Modus

Wenn Primäraktionen scheitern, kann ein zulässiger Recovery-Kandidat als EXECUTE_RECOVERY gewählt werden.

Integration in einen Agenten

candidates = planner.propose(state)
evidences = [domain_adapter.to_evidence(c, state) for c in candidates]
decision = governor.choose(evidences, recovery_candidates=recovery_evidences)

if decision.status in ("EXECUTE", "EXECUTE_RECOVERY"):
    executor.run(decision.selected_action)
else:
    escalation_queue.submit(decision.to_json())

selected_action ist eine Aktions-ID und sollte gegen ein registriertes Kandidatenobjekt aufgelöst werden.
