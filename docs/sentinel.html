Omega Sentinel: observation without intervention.

A local telemetry agent for Omega research runs that demonstrates a practical Closure-Ethics boundary: enough autonomy to observe and report, deliberately insufficient authority to control or rewrite the system observed.

Open GitHub source ↗Omega Sentinel v0.2 source ↗Machine-readable policy ↗
Design rule: an observer should be able to reveal a failure, but should not be able to conceal it by changing the process or evidence it observes.
Operational purpose

A narrow agent with a useful job.

Processes

Research-run state

Finds relevant Python processes through psutil or layered Windows fallbacks and reports degraded observation explicitly.

Evidence

Logs and summaries

Reads bounded log tails, detects declared error patterns and reports an existing scientific classification without modifying it.

Hardware

GPU telemetry

Reads utilization, memory and temperature through nvidia-smi; missing telemetry becomes visible rather than fabricated.

Local state

Dashboard

Refreshes a human-readable dashboard and machine-readable latest state on a 30-second default cycle.

Audit

Closure decisions

Records the policy decision associated with each declared read and write in a local NDJSON audit trail.

Bridge

Payload, not permission

Prepares a compact local heartbeat. Publishing it is intentionally delegated to a separate, independently authorized component.

Authority map

The useful boundary is explicit.

CapabilityStatusClosure rationale
Read relevant process metadataAllowedNecessary for observation; the backend and degradation state remain attributable.
Read bounded log tails and summariesAllowedSupports failure recognition without altering scientific evidence.
Write five files under _omega_sentinelAllowedLocal, named, replaceable telemetry with zero declared scientific or external effect.
Start, stop or restart a processDeniedObservation authority does not compose into intervention authority.
Modify or delete scientific filesDeniedPreserves evidence, reversibility and the independence of the monitored run.
Network access or GitHub publicationDeniedCommunication output does not imply identity, credentials or publishing authorization.
Privilege change or persistence expansionDeniedThe observer cannot silently enlarge its own operating boundary.
Control topology

Separation of powers in a small system.

Observation path

research run → bounded readers → Sentinel state → Closure Kernel → local telemetry

External path

bridge.json → separately authorized publisher → GitHub. The second arrow is not implemented inside Sentinel.

Why this matters

If monitoring, intervention and publication share one undifferentiated authority, a defect or compromised agent can change the process, rewrite the evidence and publish a misleading account. Omega Sentinel keeps those powers structurally separate.

Scientific boundary

A demonstrator, not an alignment claim.

Omega Sentinel shows that a Closure-Ethics principle can be translated into a concrete software authority boundary. It does not establish moral correctness, solve general AI alignment or secure the surrounding operating system. The kernel governs the Sentinel's declared I/O; deployment permissions and any external publisher require independent controls.
